# Syncra — Дизайн-бриф

> **Кому:** дизайн-агенту.
> **Задача:** спроектировать интерфейс менеджера паролей Syncra под **две среды — мобильную (iOS) и десктоп (Windows/Linux + браузерное расширение)**.
> **Как пользоваться:** это самодостаточный бриф. Технический spec-документ читать не обязательно; всё, что влияет на экраны и UX, собрано здесь. Если чего-то не хватает — считать это зоной твоей дизайнерской свободы, но не противоречить принципам ниже.

---

## 1. Что это за продукт (в двух абзацах)

**Syncra** — децентрализованный менеджер паролей. Ключевое отличие от Bitwarden/1Password: **у него нет сервера и нет облака.** Пароли живут на устройствах пользователя и синхронизируются напрямую между ними по локальной сети (дома, за одним роутером). Пользователь полностью владеет своими данными.

Из этого вытекает эмоциональный посыл дизайна: **приватность, контроль, спокойствие, «это только твоё».** Не «корпоративный сейф», а personal, доверительный, но при этом технически надёжный инструмент. Продукт должен выглядеть современно и заслуживающе доверия — от менеджера паролей люди ждут ощущения безопасности на уровне визуала.

---

## 2. Целевые среды и их различия

Нужны **обе** среды. Проектируй адаптивно, но не «одно растянутое на всё» — учитывай различия паттернов.

| | Мобайл (iOS) | Десктоп (Windows/Linux) + расширение |
|---|---|---|
| Основной ввод | тач, одна рука | мышь + клавиатура |
| Разблокировка | Face ID / Touch ID / пароль телефона, фолбэк — мастер-пароль | PIN, фолбэк — мастер-пароль |
| Автозаполнение | системный AutoFill (шторка над клавиатурой) | браузерное расширение (dropdown в поле логина) |
| Навигация | нижний таб-бар / стек | сайдбар + основная область (двухпанельно) |
| Плотность | крупные тач-таргеты, вертикальный поток | выше плотность, списки+детали рядом |

Браузерное расширение — это **отдельный, очень компактный контекст** (маленький попап + inline-подсказка в поле ввода), спроектируй его отдельно от «большого» десктоп-приложения.

## 3. Ключевые экраны (обязательный минимум)

### 3.1. Список паролей (главный экран)
- Список записей. В строке видно: **имя сервиса, логин, метка аккаунта** (если есть), иконка-заглушка.
- **Иконки — локальные заглушки** (первая буква / генеративный аватар по домену). ❗**Не тянуть фавиконы из интернета** — это утечка «какими сервисами пользуется человек» стороннему серверу, что противоречит философии продукта. Дизайн заглушек — на тебе.
- Поиск, сортировка. Быстрое действие «скопировать пароль» прямо из списка.
- **Пароль в списке НИКОГДА не показан открыто** — только по явному действию (см. reveal, §3.3).
- Учти пустое состояние (нет паролей) и состояние «только что импортировал, вот они».

### 3.2. Секции / Vaults
- Пароли группируются в **секции** («Личное», «Рабочее»). По умолчанию всё в одном пространстве, пользователь может делить.
- Нужен способ переключения/фильтрации по секции. На десктопе — вероятно, в сайдбаре; на мобайле — фильтр/таб.

### 3.3. Карточка записи (детали) + reveal секретов
Поля делятся на два визуальных класса — **это центральный принцип экрана:**
- **Метаданные (видны сразу):** имя сервиса, список URL, логин, метка аккаунта, даты (создано / изменён пароль).
- **🔒 Секреты (скрыты по умолчанию, показываются по явному reveal):** пароль, заметки, TOTP-секрет.
- Для каждого секрета: кнопка «показать/скрыть» + «скопировать». Скопированное желательно авто-очищать из буфера через N секунд (покажи это в UX).
- Покажи «возраст пароля» дружелюбно (напр. «паролю 2 года — стоит обновить») — это фича гигиены, но не делай её навязчивой/тревожной.

### 3.4. Создание/редактирование записи + генератор паролей
- Форма записи со всеми полями выше.
- **Генератор паролей** встроен в поле пароля. Логика: пользователь **один раз** настраивает профиль генерации (длина, наборы символов), а при генерации получает **несколько вариантов на выбор** (N штук). Спроектируй и «быстрый выбор из вариантов», и «настройки профиля» отдельно.

### 3.5. Мультиаккаунт-пикер (важный экран для автозаполнения)
- Сценарий: на одной странице (напр. `google.com`) у пользователя **несколько аккаунтов**. Система **не угадывает**, а **показывает список на выбор**.
- Записи в пикере различаются по **логину и метке аккаунта** («личный» / «рабочий»).
- Этот пикер существует в двух формах: системный AutoFill на iOS (шторка) и dropdown расширения на десктопе. Спроектируй обе.

### 3.6. Сопряжение устройств (Pairing) — фирменный момент
- Новое устройство добавляется через **QR-код**: на одном устройстве показывается QR, другим — сканируется.
- Это ключевой «вау/доверие» момент онбординга (у продукта нет аккаунтов — вместо «войти по email» ты «знакомишь устройства»). Спроектируй красиво и понятно: состояния «показываю QR» / «сканирую» / «успешно сопряжено».
- Экран списка **доверенных устройств** + возможность **отозвать (revoke)** устройство (сценарий «украли ноутбук»).

### 3.7. Диалог разрешения конфликта
- Сценарий: одну запись изменили на двух устройствах офлайн. При синхронизации нужно показать **обе версии целиком с полным diff** (что отличается) и **датами** (какая раньше, какая позже).
- Пользователь выбирает **одну версию целиком** (не собирает по кусочкам). Сделай diff читаемым: подсветить изменённые поля.

### 3.8. Разблокировка (unlock)
- Мобайл: экран с Face ID / Touch ID, фолбэк на мастер-пароль.
- Десктоп: PIN, фолбэк на мастер-пароль.
- Первый вход = ввод мастер-пароля (он первичен; биометрия/PIN — это удобство поверх него).

### 3.9. Онбординг / инициализация
- Первый запуск: создать хранилище, задать мастер-пароль, (опц.) включить биометрию/PIN.
- Внятно объясни модель «нет сервера, данные только на твоих устройствах» — это непривычно, пользователя надо провести за руку.
- Ветка «у меня уже есть Syncra на другом устройстве» → ведёт в pairing (§3.6).

### 3.10. Импорт / Экспорт (в настройках)
- **Импорт** из других менеджеров (jump-start) — важен для первого опыта.
- **Экспорт двух видов, визуально различить их по риску:**
  - **Зашифрованный бэкап** (безопасно, «на чёрный день») — нейтрально/спокойно.
  - **CSV** (расшифрованный, для миграции) — ❗**с явным предупреждением об опасности** («файл не зашифрован, удали после использования»). Не прячь риск, но и не пугай чрезмерно.

### 3.11. Настройки
- Профиль генератора паролей, управление секциями, устройства/revoke, импорт/экспорт, смена мастер-пароля, поведение авто-блокировки и авто-очистки буфера.

## 4. Сквозные UX-принципы (применять везде)

1. **Секреты по умолчанию скрыты.** Пароль/заметки/TOTP не мелькают на экране без явного действия. Это и безопасность, и сигнал доверия.
2. **Никаких утечек наружу.** Не показывай ничего, что предполагает обращение к внешним серверам (фавиконы, аватарки из сети, «синхронизация с облаком»). Продукт гордится тем, что оффлайн.
3. **Система не угадывает секреты за пользователя** — при неоднозначности (мультиаккаунт, конфликт) показывает выбор.
4. **Состояние синхронизации должно быть видимым и спокойным.** Пользователю важно понимать «синхронизировано / есть несинхронизированные изменения / рядом нет других устройств». Придумай ненавязчивый индикатор, без тревожности.
5. **Копирование — первичное действие.** Люди в основном копируют пароль/логин. Сделай это одним движением везде, где показана запись.
6. **Доверие через ясность, а не через «замочки-страшилки».** Тон — спокойная уверенность.

## 5. Что НЕ входит в скоуп (не проектировать)

- Android, macOS — вне скоупа.
- Вложения/файлы в записях, теги, произвольные кастомные поля, хранение банковских карт/удостоверений — **не проектировать** (продукт сфокусирован на паролях).
- Экраны «облачного аккаунта», регистрации по email, восстановления пароля через email — **их нет по определению** (нет сервера).
- Запоминание «какой аккаунт по умолчанию на этой странице» — не в MVP.

---

## 6. Приоритет для MVP (если нужно расставить фазы)

- **MVP 1 (десктоп-фокус):** список, карточка+reveal, создание/генератор, секции, pairing+устройства+revoke, конфликт-диалог, разблокировка, онбординг, импорт/экспорт.
- **MVP 2:** мобайл (iOS) + оба варианта автозаполнения (iOS AutoFill, dropdown расширения) + мультиаккаунт-пикер в этих контекстах.

Спроектируй с прицелом на обе, но если нужно с чего-то начать — начни с десктопа и общей дизайн-системы, затем адаптируй под мобайл и компактный контекст расширения.

---

## 7. Что хочется получить на выходе

1. **Дизайн-систему / визуальный язык:** палитра, типографика, иконки-заглушки, компоненты (поле-секрет с reveal, строка списка, кнопка копирования, индикатор синка, QR-экран).
2. **Ключевые экраны** из §3 в **обеих средах** (мобайл + десктоп), плюс компактный вид расширения.
3. **Тёмную и светлую темы** (для менеджера паролей тёмная тема почти обязательна).
4. Явно показанные **состояния**: пустые, загрузка/синхронизация, ошибка, «нет других устройств рядом», reveal-открыто/скрыто.

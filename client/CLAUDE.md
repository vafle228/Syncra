# CLAUDE.md — Syncra Frontend (Vue SPA)

Оперативная памятка для агента по **фронтенд-части** Syncra. Читается в начале каждой сессии.
Источник истины по продукту — `syncra-spec.md` (см. «Где что лежит»). Здесь — только рабочие рельсы для этой папки, не пересказ спека.

## Что это за папка

Vue SPA — **единственная «морда» на все платформы** (десктоп + iOS). Только представление и взаимодействие с пользователем.

- Rust-ядро (крипта, сеть, БД, синхронизация, доверие) живёт в **отдельной папке** и здесь **не редактируется**.
- Нативные интеграции (iOS AutoFill на Swift, браузерное расширение) — тоже отдельные папки.
- Фронт и бэк ведутся **независимо**. Эта часть разрабатывается против **мок-ядра** (см. «Граница с ядром»), а не ждёт готовности Rust.

## Закон №1 (нарушать нельзя)

**UI ничего не знает о секретах, ключах и сети.** Вся security-критичная логика — в Rust-ядре и никогда не покидает его в открытом виде.

- Расшифрованный секрет (`password`, `notes`, `totp_secret`) попадает в UI **только** в момент явного reveal/копирования, приходит разово через IPC и **не сохраняется**: ни в сторе (Pinia), ни в `localStorage`, ни в замыкании компонента дольше показа. Авто-скрытие и очистка буфера обмена по таймеру.
- В сторе и списках живут **только метаданные** (`service_name`, `urls`, `login`, `account_label`, даты, `version`).
- Во фронте **нет крипто-кода вообще.** Никакого шифрования / KDF / подписи на JS. Если задача выглядит так, будто это надо написать здесь, — это сигнал, что она принадлежит ядру. Останови и уточни.
- Никаких секретов в логах, телеметрии, сообщениях об ошибках, снапшотах состояния.
- Фавиконы — **только локальные заглушки/буквы.** Не тянуть иконки из интернета: это утечка «какими сервисами пользуешься» стороннему провайдеру и нарушение принципа local-first.

## Граница с ядром: IPC — единственный канал

Всё общение с ядром идёт через **один типизированный IPC-клиент** (commands/events Tauri).

- Компоненты **никогда** не вызывают Tauri `invoke()` напрямую — только через типизированный клиент `src/core/ipc.ts`.
- IPC-контракт (имена команд, формы запросов/ответов, события) описан в `src/core/contract.ts` и является **договором с бэкенд-агентом**. Меняешь контракт → фиксируешь здесь и отмечаешь в `TASKS.md`.
- Пока реального Rust-ядра нет, клиент резолвится в **мок-реализацию** (`src/core/mock/`) — in-memory фейк-ядро с теми же сигнатурами, сид-данными, задержками и эмуляцией ошибок. Вся UI-разработка и тесты идут против мока. Реальный и мок-клиент **взаимозаменяемы за одним интерфейсом**, переключение — одной точкой.

## Стек

- Vue 3 (`<script setup>`) + **TypeScript** (strict).
- Vite (сборка), Tauri 2 IPC (мост к ядру).
- Pinia (состояние), Vue Router (навигация).
- Vitest + Vue Test Utils (тесты), ESLint + Prettier.

> Новые зависимости помимо перечисленных — **не добавлять без согласования.**

## Команды

- `npm run dev` — дев-сервер (против мок-ядра)
- `npm run build` — прод-сборка
- `npm run typecheck` — `vue-tsc`
- `npm run lint` — ESLint
- `npm run test` — Vitest

Требуется **Node ≥ 22.18** (см. `engines`): на Node 20 не стартуют vitest-тесты в jsdom.

## Definition of Done (для любой задачи)

1. `npm run typecheck` — чисто.
2. `npm run lint` — чисто.
3. `npm run test` — зелёно; на новую логику есть тесты.
4. Работает против мок-ядра (демо-путь проверяется руками или тестом).
5. Соответствует макетам и **Закону №1** (секрет не оседает в состоянии — проверяемо тестом там, где применимо).

## Конвенции

- Компоненты — `PascalCase.vue`; composables — `useXxx.ts`; сторы — `useXxxStore`.
- Бизнес-состояние — в сторах; компоненты тонкие.
- Стили: цвета, типографику, отступы, темы брать из **токенов дизайн-системы** (из макетов Claude Design), не хардкодить.
- Тексты предупреждений безопасности (напр. про CSV-экспорт) — брать из спека/дизайна дословно, **не смягчать**.

## Данные (кратко; полностью — §4 спека)

Запись = метаданные + секреты. Секреты во фронте **не кэшируются**.
Матчинг и группировка аккаунтов — по `urls[]` и `login`/`account_label`, **не** по `service_name` (он не уникален).
Несколько аккаунтов на один сервис — это **норма и первоклассный сценарий**, а не коллизия; группировка чисто визуальная (§4.4). Система при неоднозначности **не угадывает** — показывает пикер.
